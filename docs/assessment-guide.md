## Automated runtime evidence

On a successful CI run, the workflow uploads an artifact named
`accounts-capstone-evidence`. It contains:

- `rest-create-done`, `rest-list-done`, `rest-read-done`,
  `rest-update-done`, `rest-delete-done` — real cURL requests and responses
  against the running service.
- `security-headers-done` — actual nose test output.
- `kube-app-output` — JSON response from the service root endpoint.
- `kube-images` — actual Docker image listing produced by the CI runner.

The Actions run itself is the source for question 19. Open the successful run and
use its complete job log. The latest successful run is also reflected by the README badge.

## Items requiring a real GitHub Projects / Kubernetes / Tekton environment

The assignment asks for screenshots of board columns and sprint planning. GitHub
Issues are present, but this repository integration cannot create or capture the
GitHub Projects board UI. Open the repository's Projects page, add the listed issues,
and move them into the requested columns before taking the named screenshots.

The `Kubernetes Deployment Evidence` workflow provisions a temporary kind cluster,
builds and loads the image, deploys PostgreSQL and the Accounts service, installs
Tekton, and attempts the CD PipelineRun. When successful, it uploads an artifact
named `accounts-kubernetes-evidence` containing `kube-deploy-accounts` and
`pipelinerun.txt`. Check that workflow's final conclusion before using those files.
The GitHub Projects board screenshots still have to be captured from the actual
Projects UI; the Issues list and sprint allocation above are planning support, not
substitute screenshots.
